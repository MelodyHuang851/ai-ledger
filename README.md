# 一句账 ✦ AI 记账

> 记账的意义不是记录过去，而是改变下一笔。

一句话记账 → 即时预算冲击 → 超支提前预警 → 自然语言复盘。
零依赖本地原型：Node 22 原生 http + fetch，JSON 文件存储，前端单文件。

## 解决什么问题

传统记账 App 的真正痛点不是"记"，而是**发现超支时钱已经花完了**。
一句账把"发现超支"从月底账单提前到三个时刻：

| 时刻 | 场景 | 产品机制 |
| --- | --- | --- |
| 事前 | 花钱之前 | 打开就看到「今日还能花 ¥86」＝ 剩余预算 ÷ 剩余天数 |
| 事中 | 记账当下 | 记一笔立刻反馈冲击："这顿占餐饮预算 14%，够再来 6 次" |
| 事后 | 任意时刻 | 直接问它："这个月吃饭花了多少？""按现在的节奏月底会超吗？" |

再加一层**支出节奏预测**：按当月日均外推月底总支出，并对比"支出进度 vs 时间进度"——花钱速度跑赢时间进度就变色预警，月初第 3 天就能知道"照这个速度要超 ¥380"。

## 架构：LLM 的边界画在哪

```
用户一句话
   │
   ▼
┌──────────────┐  一次 LLM 调用做意图路由
│  GLM 解析     │──▶ 记账   ──▶ 白名单校验 ──▶ 落库 ──▶ 本地计算预算冲击
│ (人话 → JSON) │──▶ 调预算 ──▶ 校验类目/金额 ──▶ 本地修改预算
│              │──▶ 提问   ──▶ 本地聚合统计 ──▶ LLM 只负责组织语言回答
└──────────────┘
```

**核心原则：LLM 只做"人话 ⇄ 结构化"的翻译，所有算术（预算、冲击、预测、聚合）由本地确定性代码完成。**

为什么这样切：

1. **准确性** —— LLM 算术不可靠，而预算差一块钱都是错的
2. **隐私** —— 账目明细不出户，提问时只把聚合结果交给模型
3. **成本** —— prompt 里只出现必要的结构化数据，token 花在刀刃上
4. **可测** —— 核心账务逻辑是纯函数，可以单测；LLM 输出全部过白名单校验

## 工程细节

- **意图路由**：同一个输入框，一次 LLM 调用识别记账 / 调预算 / 提问三种意图，无需切换模式
- **LLM 输出容错**：markdown 代码块包裹剥离、JSON 起点定位、字段白名单过滤、日期格式归一化（`2026-8-28` → `2026-08-28`）
- **时区坑**：`toISOString()` 是 UTC，早上 8 点前“今天”会变成昨天；全部改用本地时区计算
- **运行环境兼容**：全局 fetch 要 Node 18+ 才有，检测不到时自动退回原生 `https.request`——在 Node 14 的老机器上也能跑
- **Human-in-the-loop**：AI 解析结果一键撤销，信任但可纠错
- **零依赖**：Node 22 原生 http + fetch，clone 即跑，无 node_modules

```bash
node server.js
# 3. 打开 http://localhost:3456
```
